# Internationalisation (i18n)

## Decision (2026-09-19)

L'application supporte officiellement **2 langues** : francais (`fr`,
langue par defaut) et anglais (`en`). Les 4 autres langues qui existaient
dans le code (`es`, `de`, `pt`, `ar`) restent presentes sur disque
(`locales/{es,de,pt,ar}/`, contenu reel et traduit, pas supprime) mais ne
sont plus offertes via l'interface -- decision produit, pas une suppression
de travail existant.

## Ou la limite est appliquee

Une seule source de verite cote backend : `api/config.py`,
`UI_SUPPORTED_LANGUAGES`, maintenant `["fr", "en"]` (`UI_DEFAULT_LANGUAGE`
= `"fr"`). Tout le reste du systeme en decoule automatiquement, sans
duplication de logique :

- `api/services/i18n.py` -- `get_supported_languages()` lit directement ce
  reglage ; `detect_user_language()` (cookie puis en-tete `Accept-Language`
  du navigateur puis defaut) ne retient jamais une langue hors de cette
  liste.
- `api/routers/i18n.py` -- `GET /i18n/translations/{language}` renvoie 404
  et `POST /i18n/language` renvoie 400 pour toute langue hors `fr`/`en` ;
  aucun changement de code necessaire ici, la verification existait deja
  et lit la meme liste.
- `frontend/components/LanguageSelector.tsx` (nouveau) -- la liste
  affichee cote UI (`FR`/`EN`) doit rester synchronisee manuellement avec
  `UI_SUPPORTED_LANGUAGES` ci-dessus ; en cas de desaccord entre les deux,
  le backend reste la limite reellement appliquee (l'UI n'empecherait pas
  un appel direct a l'API avec une autre langue, mais l'API le refuserait).

## Le vrai selecteur de langue (nouveau)

Bug reel trouve en verifiant ce point : `frontend/lib/i18n.tsx` exposait
deja un `setLanguage()` fonctionnel (avec son propre appel reel a
`POST /i18n/language`), mais **aucun composant ne l'appelait jamais** --
il n'existait donc aucun moyen reel de changer de langue depuis
l'interface avant ce correctif, malgre toute la plomberie backend/hook
deja en place. `components/LanguageSelector.tsx` est le premier vrai
appelant : deux boutons `FR`/`EN`, montes dans le layout du dashboard
(pres du bouton de deconnexion) et dans l'en-tete de la page de
conversation.

Note : `components/LanguageSwitcher.tsx` (le widget Google Translate) est
un composant different, deja desactive plus tot dans le projet a cause
d'un bug de gel de page au moment de la navigation -- il n'est monte nulle
part et n'est pas concerne par ce changement.

## Fichiers de traduction

`locales/fr/*.json` et `locales/en/*.json` -- 3 categories chacun
(`common.json`, `chat.json`, `widget.json`), deja completes et testees
avant ce changement. Aucune modification necessaire a leur contenu pour
cette limitation a 2 langues.
