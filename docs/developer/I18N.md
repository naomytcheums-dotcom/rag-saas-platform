# Sélecteur de langue (traduction du site)

## Composant

[`frontend/components/LanguageSwitcher.tsx`](../../frontend/components/LanguageSwitcher.tsx)
— un petit wrapper autour du package
[`next-google-translate-widget`](https://www.npmjs.com/package/next-google-translate-widget),
utilisé dans le tableau de bord ([`app/dashboard/layout.tsx`](../../frontend/app/dashboard/layout.tsx))
et la page de conversation ([`app/chat/page.tsx`](../../frontend/app/chat/page.tsx)).

```tsx
import LanguageSwitcher from "@/components/LanguageSwitcher";

<LanguageSwitcher />
```

## Pourquoi ce package (remplace l'ancien composant maison)

L'ancien `components/GoogleTranslate.tsx` pilotait le widget brut de Google (un
`<select>` caché) via un menu de drapeaux fait main. Il fonctionnait globalement, mais
avait un vrai défaut rapporté : après un cycle traduction/rechargement, React levait
parfois une erreur `removeChild`, car le script de Google modifie des nœuds du DOM que
React croit encore posséder.

`next-google-translate-widget` monte le widget dans son propre conteneur isolé — React
n'a donc plus rien à perdre de vue. Il apporte aussi, sans code supplémentaire :
- un menu déroulant avec glassmorphism et drapeaux, déjà cohérent visuellement ;
- la persistance de la langue choisie via `localStorage` ;
- le passage fiable entre deux langues non-anglaises (l'ancien composant nécessitait un
  contournement manuel par cookie pour ce cas précis).

## Configuration actuelle

- **Langue source de la page** : `fr` (le contenu réel de l'application est en français).
- **5 langues proposées** : Anglais, Espagnol, Français, Allemand, Portugais — filtrées
  depuis la liste `LANGUAGES` exportée par le package.
- **Thème** : classe CSS `app-translate`, définie dans
  [`app/globals.css`](../../frontend/app/globals.css), qui surcharge les variables
  `--ngt-*` du package pour matcher la palette claire/orange du site. Les surcharges sont
  en `!important` car le package redéfinit ces mêmes variables sous
  `@media (prefers-color-scheme: dark)` — ce site a une règle de conception explicite et
  permanente : **jamais de mode sombre**, donc la préférence système de l'utilisateur ne
  doit jamais changer l'apparence du sélecteur.

## Comment ça fonctionne (résumé)

Le composant charge le script de traduction de Google et monte le widget dans un
`<div>` caché. Au choix d'une langue, il écrit le cookie `googtrans` que Google lit, puis
recharge la page — le script de Google traduit alors tout le contenu rendu. La sélection
est mémorisée dans `localStorage`.

**Limite connue, assumée** : un rechargement complet de page à chaque changement de
langue (imposé par le mécanisme de cookie de Google Translate) — comportement identique à
l'ancien composant, aucune régression introduite.

## Vérification effectuée

Testé en direct dans le navigateur (pas seulement lu dans la doc du package) :
- Français → Anglais : traduction instantanée de toute la page (sidebar + contenu).
- Persistance : rechargement de la page après passage en anglais → reste en anglais.
- Anglais → Allemand directement (sans repasser par le français) : traduction correcte,
  y compris le titre de l'onglet du navigateur.
- Allemand → Français directement : traduction correcte.
- Aucune erreur `removeChild` (ni aucune autre erreur React) dans la console à aucune
  étape de ces changements de langue.
