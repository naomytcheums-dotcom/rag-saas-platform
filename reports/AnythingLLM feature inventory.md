# AnythingLLM's 2026 feature surface, mapped for KnowFlow

AnythingLLM remains, at its core, a single **MIT-licensed** monorepo (`Mintplex-Labs/anything-llm`) with no open-core split and no relicensing history since its June 2023 initial commit ([LICENSE](https://github.com/Mintplex-Labs/anything-llm/blob/master/LICENSE), [GitHub Commits API](https://api.github.com/repos/Mintplex-Labs/anything-llm/commits?path=LICENSE)) — the one carve-out is an experimental, not-yet-integrated `open-computer` subdirectory under AGPLv3, inherited from a bundled QEMU submodule ([open-computer/LICENSE](https://github.com/Mintplex-Labs/anything-llm/blob/master/open-computer/LICENSE)). Monetization runs through a separate managed **AnythingLLM Cloud** product (Basic $50/mo, Pro $99/mo, custom Enterprise) that is, counterintuitively, a *functional subset* of the free Docker build: Cloud explicitly disables custom Agent Skills and MCP support and ships no bundled local LLM, for security and hardware reasons ([Cloud Limitations](https://docs.anythingllm.com/cloud/limitations), [anythingllm.com/pricing](https://anythingllm.com/pricing)). Feature depth is genuinely large and still growing fast: the codebase now integrates roughly **38–40 LLM providers**, **10 vector databases**, and **14 embedding engines** ([AiProviders](https://github.com/Mintplex-Labs/anything-llm/tree/master/server/utils/AiProviders), [vectorDbProviders](https://github.com/Mintplex-Labs/anything-llm/tree/master/server/utils/vectorDbProviders), [EmbeddingEngines](https://github.com/Mintplex-Labs/anything-llm/tree/master/server/utils/EmbeddingEngines)), plus a mature agent stack (built-in skills, custom NodeJS "Agent Skills," no-code "Agent Flows," and native MCP client support added in v1.8.0). The most important structural fact for a KnowFlow gap-analysis is the three-way split across deployment forms: **Docker self-host** is the "full product" (multi-user RBAC, embeddable widget, white-labeling, agents, MCP); **Desktop** is a deliberately single-user, bundled-local-stack app missing all of those team features; and **Cloud** sits in between — multi-tenant-adjacent and paid, but stripped of exactly the power-user features (custom code execution, MCP) that a hosted SaaS vendor would find riskiest to run multi-tenant. Several claims below — SSO existence, exact chunking limits, citation UI mechanics, and precise Cloud resource specs — could not be confirmed from primary sources and are flagged explicitly rather than asserted.

## 1. Workspaces isolate configuration, not just documents

A workspace in AnythingLLM is the unit of configuration isolation: the live Prisma schema confirms persisted per-workspace fields for `openAiTemp` (temperature), `openAiHistory` (history length, default 20), `openAiPrompt` (system prompt override), `similarityThreshold` (default 0.25), `chatProvider`/`chatModel` (LLM override), `topN` (context snippet count, default 4), `chatMode`, and — separately — `agentProvider`/`agentModel` for overriding the model used specifically inside Agent Mode ([schema.prisma](https://raw.githubusercontent.com/Mintplex-Labs/anything-llm/master/server/prisma/schema.prisma)). This means a single workspace can run ordinary chat on a cheap local Ollama model while escalating to a stronger model only when an agent session's tool-calling kicks in — a meaningful cost/latency lever KnowFlow should weigh against its own model-routing design. Three chat modes exist: **Agent Mode** (auto-invokes tools via native function-calling), **Chat Mode** (blends retrieved context with the model's general knowledge), and **Query Mode** (answers strictly from uploaded documents, with a configurable similarity-threshold gate — No restriction/Low ≥.25/Medium ≥.50/High ≥.75 — and a customizable `queryRefusalResponse` string returned when nothing relevant is found) ([Chat Modes docs](https://docs.anythingllm.com/features/chat-modes)). All of this is **Community/MIT**, identical across Docker and Desktop as far as the research could confirm; no distinct "Cloud workspace" limits were found, which is itself a gap rather than a confirmed absence ([workspaces_and_rag notes, Gaps section]). Two mechanics remain genuinely unconfirmed and worth a targeted follow-up before treating them as settled: exactly how vector-space isolation is implemented at the DB layer (a `vectorTag` field exists on the workspace record, suggesting metadata-tag filtering, but this wasn't verified against provider code — [DeepWiki: Workspace Model](https://deepwiki.com/Mintplex-Labs/anything-llm/8.1-workspace-model-and-configuration)), and what alternate values `vectorSearchMode` supports beyond its `"default"` (the Cloud limitations page's mention of an "Accuracy Optimized" mode that can slow down large workspaces hints at least one alternate retrieval strategy — [Cloud Limitations](https://docs.anythingllm.com/cloud/limitations)).

## 2. RAG ingestion is broad on formats and connectors, narrow on chunking sophistication

The collector's `ACCEPTED_MIMES` constant supports a wide format set — text/markup (`.txt`, `.md`, `.org`, `.adoc`, `.rst`, `.csv`, `.json`, `.html`), Office (`.docx`, `.pptx`, `.xlsx`, `.odt`, `.odp`), `.pdf`, `.mbox`, `.epub`, audio (`.wav`, `.mp3`, `.ogg`, `.oga`, `.opus`, `.m4a`, `.webm`, transcribed via Whisper), and some image/video types (`.png`, `.jpg`, `.webp`, `.mp4`, `.mpeg`) — with legacy binary `.doc` explicitly still unsupported ("pending development") ([collector/utils/constants.js, summarized](https://github.com/Mintplex-Labs/anything-llm/blob/master/collector/utils/constants.js)). Note this list was relayed through an AI-summarization step rather than read verbatim, so treat it as high-confidence but not byte-for-byte verified. Connector-wise, `collector/extensions/index.js` confirms a generic branch-aware Git/GitHub repo loader, YouTube transcript extraction (preferring human over auto-generated captions), a recursive "Website Depth" crawler, Confluence, Drupal Wiki, Obsidian Vault, and Paperless-NGX, plus separate (non-extension-folder) endpoints for generic web scraping and raw-text submission ([index.js](https://raw.githubusercontent.com/Mintplex-Labs/anything-llm/master/collector/extensions/index.js), [DeepWiki: Data Connectors](https://deepwiki.com/Mintplex-Labs/anything-llm/9.3-data-connectors)). GitLab is handled inside the same generic repo loader rather than as a standalone module, and pulls issues/discussions/wiki pages in addition to code per community reports ([Issue #4571](https://github.com/Mintplex-Labs/anything-llm/issues/4571)). A standalone sitemap-XML connector was **not confirmed** to exist as a discrete feature — it may be folded into Website Depth, but this wasn't verified in code. On vector infrastructure, ten providers ship in `server/utils/vectorDbProviders`: **LanceDB** (embedded default), Astra DB, Chroma, Chroma Cloud, Milvus, PGVector, Pinecone, Qdrant, Weaviate, and Zilliz — all MIT, none paid-gated ([vectorDbProviders](https://github.com/Mintplex-Labs/anything-llm/tree/master/server/utils/vectorDbProviders)). Embedding coverage spans 14 engines: Azure OpenAI, Cohere, Gemini, Generic OpenAI, Lemonade, LiteLLM, LM Studio, Local AI, Mistral, Native (built-in, 25MB CPU model, no API key), Ollama, OpenAI, OpenRouter, and Voyage AI ([EmbeddingEngines](https://github.com/Mintplex-Labs/anything-llm/tree/master/server/utils/EmbeddingEngines)). Chunking, however, is where AnythingLLM lags more sophisticated RAG stacks: the pipeline uses a `RecursiveCharacterTextSplitter` with a flat default of **1000 characters / 20 overlap**, exposed in the UI as just two fields — "Text Chunk Size" and "Text Chunk Overlap" — with re-embedding required on change ([DeepWiki: Text Splitting](https://deepwiki.com/Mintplex-Labs/anything-llm/6.3-text-splitting-and-chunking); [Issue #490](https://github.com/Mintplex-Labs/anything-llm/issues/490)). An open feature request (#6364) for "structure-aware chunking option (per heading/topic)" confirms that **semantic or heading-aware chunking is not yet built** — a concrete gap KnowFlow could differentiate on if it supports structure-aware splitting for SOPs or long structured documents ([Issue #6364](https://github.com/Mintplex-Labs/anything-llm/issues/6364)). Citation/source-attribution UI mechanics in chat responses could not be confirmed from any source reached in this research pass and should be treated as an open question, not an assumed capability gap.

## 3. Agents layer three distinct extension mechanisms, but Cloud shuts two of them off

AnythingLLM's agent system invokes either automatically (for LLMs with native tool-calling) or manually via typing `@agent`, ending on completion or `/exit` ([Agent Usage docs](https://docs.anythingllm.com/agent/usage/overview)). Roughly ten built-in skills ship out of the box — RAG Search, Web Browsing, Web Scraping, Save Files, List Documents, Summarize Documents, Chart Generation, SQL Agent, File System Agent, Create Scheduled Jobs — with some documentation inconsistency over whether Gmail/Calendar/Outlook/Document-Generation agents are core built-ins or Community Hub add-ons (flagged as unresolved rather than settled either way) ([Agent Usage docs](https://docs.anythingllm.com/agent/usage/overview); [Custom Agent Skills intro](https://docs.anythingllm.com/agent/custom/introduction)). Beyond built-ins, three extension layers exist. First, **Custom Agent Skills**: NodeJS plugins (`plugin.json` + `handler.js`) hot-loaded from `plugins/agent-skills/[hubId]/`, capable of "operating-system invocations," available on Docker (since v1.2.2) and Desktop (since v1.6.5) but **explicitly excluded from Cloud** — a clear, security-motivated restriction given Cloud's multi-tenant hosting ([Custom Agent Skill Developer Guide](https://docs.anythingllm.com/agent/custom/developer-guide)). Second, the **Community Hub** (hub.anythingllm.com, still in beta) lets users publish/share Agent Skills, System Prompts, and Slash Commands via a CLI tool, though the live skill count couldn't be verified since the listing page returned HTTP 403 to automated fetch ([Community Hub docs](https://docs.anythingllm.com/community-hub/about)). Third, **Agent Flows** — a no-code, drag-and-drop visual builder for chaining API calls, LLM steps, and file operations, runnable on-demand or via cron, and also MCP-compatible — ships on Docker and Desktop with unconfirmed but likely-absent Cloud support, following the same pattern as Custom Skills ([Agent Flows overview](https://docs.anythingllm.com/agent-flows/overview)). Native **MCP client support** (StdIO, SSE, and Streamable transports, configured via `anythingllm_mcp_servers.json`) launched as a major feature in v1.8.0, with continued investment through v1.10.0 (June 24, 2026) adding Docker Model Runner integration ([MCP Compatibility docs](https://docs.anythingllm.com/mcp-compatibility/overview)). Critically, **Cloud explicitly disables MCP** alongside custom Agents, for the identical "arbitrary code in a hosted environment" security rationale ([Cloud Limitations](https://docs.anythingllm.com/cloud/limitations)) — meaning AnythingLLM's most powerful extensibility surface is entirely unavailable to anyone paying for the managed product, a genuine asymmetry KnowFlow's positioning could exploit if it offers safer sandboxed extensibility in a hosted tier. AnythingLLM functioning as an MCP *server* (rather than client) remains community-built only; an official first-party version is still an open feature request (#6403) ([Issue #6403](https://github.com/Mintplex-Labs/anything-llm/issues/6403)).

## 4. Model coverage is enormous and fully OSS, but "AnythingLLM Cloud" caps it at the edges

The `server/utils/AiProviders` directory lists 40 provider folders (roughly 38 genuine third-party integrations once router/mapping utilities are excluded), spanning majors (OpenAI, Anthropic, Azure OpenAI, AWS Bedrock, Google Gemini/Vertex), aggregators (OpenRouter, LiteLLM, APIpie), and a long tail of newer inference platforms (Cerebras, DeepSeek, Fireworks AI, Groq, Moonshot AI, Novita, NVIDIA NIM, SambaNova, xAI, Zai, and more) — all Community/MIT, with no evidence any is gated behind a paid tier in the self-hosted product ([AiProviders directory](https://github.com/Mintplex-Labs/anything-llm/tree/master/server/utils/AiProviders)). Local inference is treated as first-class: Ollama, LM Studio, Local AI, KoboldCPP, oMLX, Text-Generation-WebUI, Lemonade, and llmman each have dedicated modules, alongside a first-party **"AnythingLLM Default"** built-in LLM and matching **"AnythingLLM Default Embedder"** (25MB, CPU-only, auto-downloaded, no API key) that let the product run fully offline out of the box ([AnythingLLM Default docs](https://docs.anythingllm.com/setup/llm-configuration/local/built-in); [Default Embedder docs](https://docs.anythingllm.com/setup/embedder-configuration/local/built-in)). GPT4All, an early AnythingLLM-associated local-model project, no longer appears in the current source tree and should be treated as removed/superseded. Per-workspace model override is granular at both provider and model level simultaneously, and — per a corroborating GitHub issue title — apparently separately overridable for Agent-mode sessions specifically ([Issue #1294](https://github.com/Mintplex-Labs/anything-llm/issues/1294); [Workspace Model docs](https://deepwiki.com/Mintplex-Labs/anything-llm/8.1-workspace-model-and-configuration)). The sharpest deployment-form distinction here is Cloud's: it ships **no bundled/local LLM at all** ("lacks a bundled language model due to hardware constraints... must connect to external cloud providers or run their own local LLMs instead"), and its built-in embedder can crash an instance on oversized documents rather than gracefully rejecting them ([Cloud Limitations](https://docs.anythingllm.com/cloud/limitations)). TTS spans six options (System Native, Browser-based, Piper — local, in-browser — Kokoro — self-hosted server required — OpenAI, ElevenLabs, and generic OpenAI-compatible endpoints), while STT is more limited: only Native Browser and OpenAI were confirmed, and voice input is **explicitly unavailable on Desktop** ([Text to Speech docs](https://docs.anythingllm.com/features/text-to-speech)).

## 5. Chat UX is feature-complete for a modern assistant, multi-user hinges on a one-way switch

Standard chat affordances are all present and MIT: Regenerate, Edit (destructively truncates and resubmits — no branching confirmed), thumbs up/down Feedback (purely qualitative, intended for later RLHF-style export), Copy, and Speak ([chat-ui docs](https://docs.anythingllm.com/chat-ui)). Multiple parallel conversation **threads** per workspace are supported via a `WorkspaceThread` model, with thread-scoped document uploads isolated per thread while workspace-embedded documents remain available across all threads — though a documented bug shows the developer API's thread endpoints can behave inconsistently versus the main UI ([DeepWiki: Workspace System](https://deepwiki.com/Mintplex-Labs/anything-llm/8-workspace-system); [Issue #2526](https://github.com/Mintplex-Labs/anything-llm/issues/2526)). Document **pinning** bypasses chunked retrieval entirely, injecting a document's full text into every prompt for that workspace — useful for small, mission-critical documents, but purely manual (no automatic promotion of vector-search hits into pinned status, per an open feature request) ([Issue #3587](https://github.com/Mintplex-Labs/anything-llm/issues/3587)). Chat history is exportable as CSV per workspace/user once ≥10 logs exist, and admins can globally disable history viewing (which also disables export and delete) — CSV appears to be the only export format, per still-open requests for JSONL support ([Chat Logs docs](https://docs.anythingllm.com/features/chat-logs); [Issue #341](https://github.com/Mintplex-Labs/anything-llm/issues/341)). Token-by-token streaming response support could **not be confirmed** from any source reached in this pass — a genuine gap worth a direct code check before assuming parity with typical chat UIs. On multi-user: exactly three roles exist — **Admin** (full system control), **Manager** (broad workspace/user management but no LLM/Embedder/Vector DB/API-key config access), and **Default** (restricted to explicitly-assigned workspaces only, allow-list style, with no evidence of a separate "groups" construct) — and a live GitHub issue (#5857) shows active maintainer debate that Manager's scope is currently too broad ([Security & Access docs](https://docs.useanything.com/features/security-and-access); [Issue #5857](https://github.com/Mintplex-Labs/anything-llm/issues/5857)). Multi-user mode is a **one-way, irreversible toggle** enabled from Settings → Security — once flipped on, an instance cannot revert to single-user via the standard UI ([Security & Access docs](https://docs.useanything.com/features/security-and-access)). Single-user instances separately support optional shared-password protection, togglable anytime. Multi-user itself, and by extension the entire RBAC system, is **Docker-only** — absent from Desktop, which is architecturally single-user. No native **SSO (SAML/OIDC)** support was found anywhere in official documentation, and a direct search returned nothing AnythingLLM-specific; this should be read as a likely-but-unconfirmed absence in the OSS product, especially notable since the Cloud Enterprise tier explicitly advertises "SSO, RBAC, and more" as a paid differentiator ([Security & Access docs](https://docs.useanything.com/features/security-and-access); [anythingllm.com/pricing](https://anythingllm.com/pricing)) — implying SSO may be an Enterprise-Cloud-only, services-delivered capability rather than a shippable OSS feature.

## 6. The API is a full open REST surface, but keys are coarse-grained and there's no official SDK

AnythingLLM exposes a complete developer REST API — reportedly around 58 endpoints under an OpenAPI 3.0 spec (figure sourced from search synthesis, not independently verified against the raw spec file) — covering workspace management, document embedding, and chat, browsable via an interactive Swagger UI at `/api/docs` by default (togglable off via `DISABLE_SWAGGER_DOCS` for production) ([API Access & Keys docs](https://docs.useanything.com/features/api)). This is entirely Community/MIT, not paywalled. API keys are generated/deleted on demand by permitted accounts and function as broad bearer credentials; the docs' "anyone with the key can use the API" phrasing implies keys are **not scoped** to a specific workspace, role, or endpoint subset — a coarser model than typical SaaS API-key systems, and worth flagging for KnowFlow if fine-grained key scoping is a differentiator worth building. No maximum key count or workspace-scoping mechanism was documented. No official first-party JS or Python SDK package was found; what does exist is an official terminal CLI (`@mintplex-labs/anything-llm-cli`) and a separate "Hub CLI" (`@mintplex-labs/anythingllm-hub-cli`) for agent-skill publishing — developers integrating programmatically are, per current evidence, expected to either hand-roll HTTP calls or generate a client from the OpenAPI spec themselves ([npm: anything-llm-cli](https://www.npmjs.com/package/@mintplex-labs/anything-llm-cli)).

## 7. The embed widget and admin surface are Docker-exclusive, and white-labeling excludes both Cloud and Desktop

The embeddable chat widget is confirmed **Docker-only** — absent from Desktop and, per the Cloud limitations pattern, plausibly Cloud too, though this specific point wasn't independently verified for the widget ([Chat Widgets docs](https://docs.useanything.com/features/chat-widgets)). Each embed binds to exactly one workspace via a unique `data-embed-id`, dropped in via `<script>` tag, and supports rich `data-*` customization: four-corner positioning, five icon styles, hex color theming, custom brand image, greeting text, assistant name, window sizing, language, sponsor-footer removal, and per-embed overrides for model, temperature, and system prompt ([anythingllm-embed README](https://github.com/Mintplex-Labs/anythingllm-embed/blob/main/README.md)). Domain allow-listing is first-class but **defaults to open** (any origin can query an embed with no allowlist configured) unless an admin sets the allowlist or flips the `EMBED_REQUIRE_ALLOWLIST` env var to deny-by-default — a real exposure risk operators must actively remediate. Usage governance exists via per-embed max-chats-per-day and max-chats-per-session caps (zero = unlimited), framed as cost/abuse control rather than commercial tier-gating. Notably, the widget appears to **withhold context snippets/citations** from anonymous users ("cannot access context snippets and receive randomized session IDs"), a deliberate reduction versus the authenticated main-app chat experience — and full streaming/citation parity with the main app could not be confirmed either way. On the admin side, a built-in, always-on **Event Logs** feature (Admin/Manager-only) tracks login attempts, messages sent, settings changes, and document uploads, stored locally with no confirmed retention policy or export mechanism — a real gap for enterprise-compliance buyers ([Event Logs docs](https://docs.anythingllm.com/features/event-logs)). Telemetry defaults on via PostHog, explicitly excludes PII/document content/chat logs, and is disable-able via `DISABLE_TELEMETRY` or an in-app toggle — though an open issue (#4534) suggests the opt-out historically didn't propagate to every third-party touchpoint ([Privacy docs](https://docs.anythingllm.com/features/privacy-and-data-handling); [Issue #4534](https://github.com/Mintplex-Labs/anything-llm/issues/4534)). White-labeling (custom login logo, welcome messages, footer links/icons) is documented as **exclusive to self-hosted Docker** — notably excluded from both Desktop *and* the paid Cloud product, meaning Cloud customers cannot currently rebrand their instance even though they're paying for it ([Customization docs](https://docs.useanything.com/features/customization)).

## 8. Deployment forms diverge sharply; licensing stays uniformly permissive

Three deployment forms exist with materially different capability sets. **Docker self-host** is the reference full-featured build: multi-user RBAC, embeds, white-labeling, agents, MCP, and the complete provider matrix, all free and MIT — deployable via Docker Compose, bare metal, one-click buttons (Railway, Render, DigitalOcean, AWS, GCP, RepoCloud), or an official Helm chart for Kubernetes ([README](https://raw.githubusercontent.com/Mintplex-Labs/anything-llm/master/README.md); [Mintplex-Labs/helm-charts](https://github.com/Mintplex-Labs/helm-charts)). **Desktop** (Mac/Windows/Linux) is a deliberately narrowed, single-user, one-click installer bundling its own local LLM engine, CPU embedder, and LanceDB — missing multi-user, embeds, white-labeling, agents, and voice input; whether it's literally Electron-based was not confirmed in any primary source and remains an inference. **AnythingLLM Cloud** is the paid managed tier — Basic $50/mo, Pro $99/mo, Enterprise custom-priced — running isolated single-tenant instances on AWS, explicitly positioned as easier-to-trial rather than more capable: it drops custom Agents, MCP, bundled local LLMs, and white-labeling relative to Docker, making it a functional *subset*, not superset, of the free self-hosted product ([Cloud Overview](https://docs.anythingllm.com/cloud/overview); [Cloud Limitations](https://docs.anythingllm.com/cloud/limitations); [pricing](https://anythingllm.com/pricing)). A source discrepancy is worth flagging: the Cloud Limitations page names "Starter" and "Professional" tiers while the live pricing page names "Basic," "Pro," and "Enterprise" — likely a rename over time, with the pricing page treated as current. Licensing throughout is uniform and unremarkable from a risk standpoint: root MIT since the very first commit, no dual-licensing or proprietary Enterprise Edition anywhere in the codebase, submodules (`embed`, `browser-extension`, presumably `mobile`) independently confirmed MIT, and the sole exception — `open-computer`'s AGPLv3 — is an experimental, not-yet-shipped virtual-desktop subsystem isolated from the core product ([open-computer/README](https://github.com/Mintplex-Labs/anything-llm/blob/master/open-computer/README.md)). MIT permits forking, rebranding, and commercial resale outright, with the only textual obligation being retention of the copyright/license notice; no formal Mintplex Labs trademark policy was found, meaning "AnythingLLM" branding protections rest on default common-law trademark rather than a published, citable policy — a nuance KnowFlow's legal review should note if evaluating a fork-and-rebrand strategy.

## What this means for KnowFlow

The clearest strategic signal is that AnythingLLM's paid Cloud tier is not a "more features for more money" product — it is a *safety-constrained* version of the free software, missing exactly the extensibility (custom code agents, MCP) and brand control (white-labeling) that enterprise buyers often want most. If KnowFlow can offer a hosted, multi-tenant product that safely supports custom agent logic, MCP-style tool integration, or white-labeling — the three things AnythingLLM Cloud explicitly forgoes for security reasons — that is a durable differentiation angle rather than a feature-parity race. Second, AnythingLLM's chunking is genuinely unsophisticated (flat character-count splitting, no structure/heading awareness, confirmed still-open as a feature request), so structure-aware or semantic chunking is a legitimate, verifiable technical edge rather than marketing exaggeration. Third, several open questions — SSO existence, API key scoping granularity, citation/streaming behavior in both main chat and the embed widget, and exact Cloud resource limits — were not resolvable from public documentation in this pass and should be verified directly (via a live instance or a paid Cloud trial) before KnowFlow's competitive claims rely on them, since asserting a confirmed gap that turns out to exist would undercut credibility more than leaving it as an open question does now.
